# ArnaLead 0.1

Оригинальный ручной журнал передачи лида с явным принятием новым ответственным. Референс направления: Respond.io (#4 исходного каталога), без полного повторения платформы.

## Локальный запуск

Node.js >=24.15 <25, без внешних зависимостей. `npm test` запускает15 предметных/HTTP проверок. Для первого старта задайте `WORK_ADMIN_USER` и секретный `WORK_ADMIN_PASSWORD` (14–200 символов), затем `npm start`. По умолчанию http://127.0.0.1:8792, данные `.data/workspace.sqlite`. Не коммитьте пароль/базу. `PORT`, `HOST`, `PUBLIC_ORIGIN`, `DATABASE_PATH` настраиваются окружением; внешний HTTPS/reverse proxy/резервирование отдельно.

Первый администратор создаёт отдельные аккаунты отправителя и получателя в «Данные и доступ». Публичной регистрации и общего пароля нет. Для теста используйте синтетические данные.

## Рабочий сценарий

1. Администратор может назначить существующий аккаунт, сотрудник регистрирует лид на себя.
2. Текущий ответственный предлагает передачу другому аккаунту и пишет контекст на выбранном языке лида. Владелец пока прежний. RU/KK текст авторский, перевода нет.
3. Только получатель принимает/отклоняет с основанием; отправитель отменяет. Администратор не принимает за получателя. Один ожидающий перевод на лид.
4. Принятие проверяет точный снимок и меняет владельца/версию вместе с решением в одной SQLite BEGIN IMMEDIATE транзакции. При отказе workspace и аудит не меняются.
5. Любая содержательная правка лида увеличивает версию, делая старый снимок непригодным для принятия. Отмените предложение и создайте новое. Старая форма дополнительно защищена общей revision; ввод при ошибке сохраняется, автоматического объединения нет.
6. Завершённые передачи неизменны. Архив не отменяет ожидающую передачу. Лид архивируется только закрытым и без ожидающего решения. Восстановление сохраняет снимки/цепочку ответственных.

## Копии и доступ

Администратор экспортирует JSON, восстанавливает его только в пустую область. Сначала создайте те же аккаунты. JSON не содержит паролей, аккаунтов и аудита, не подписан и не доказывает подлинность; проверки структуры/цепочки не заменяют подпись. Файл SQLite/WAL нужно резервировать согласованно отдельно. Есть журнал последних300 событий; решение содержит снимок источника. Общая revision может конфликтовать и при несвязанной правке — обновите экран.

Все сотрудники читают общую область одной организации. Назначение ограничивает изменение и принятие, не видимость. Нет tenant/филиальной изоляции, сброса паролей/отзыва сессий в UI, публичного портала, импорта, интеграций, внешних сообщений, AI, CRM, оплаты или результата продаж. Канал — метка. Внутреннее принятие не согласие клиента, не электронная подпись и не факт внешнего события. Нужны отдельные hostname для недоверенных приложений: cookie не изолируется портом.

Проверки: [verification](docs/verification.json), [источник](docs/reference-audit.md), [компании](docs/buyers.json). Серверный сценарий проверен локально; публичный GitHub содержит исходники, серверного публичного демо нет. Внешний полный аудит безопасности, нагрузка, промышленная эксплуатация и клиентская приёмка не заявлены.
